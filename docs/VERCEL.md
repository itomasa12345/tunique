# Vercelで確認用プレビューを作る

## 準備した内容

- Next.js / Node.js 24を使う構成です。
- `vercel.json` で `npm ci`、`npm run build` を指定しています。
- `.vercelignore` で写真の原本保管ディレクトリ、画面キャプチャ、ローカル生成物などをアップロード対象から除外します。表示に必要な選定写真は `public/` に入っています。
- Previewでは `SITE_URL` を設定せず、Vercelが注入する `VERCEL_URL` をSNS画像の基準URLに使用します。正式なURLが決まってから `SITE_URL` を設定します。ローカルではポート3000です。
- 検索掲載は停止したままです。フォームは送信・保存しません。
- ファビコンは仮のTマークです。正式なロゴ原本へ差し替える項目として残しています。

## 現在の未接続事項

この作業環境にはVercelログイン、プロジェクト連携、Vercelトークンの設定がありません。
Vercelプロジェクト作成・アップロード・プレビューURLの発行は未実施です。
GitHubのリモートには、今回のサイト実装をまだ送信していません。
チャットへパスワードやトークンを貼らないでください。

## 初回のアカウント作成

ユーザーはVercel未登録であることを確認済みです。

1. 本人のブラウザで https://vercel.com/signup を開く。
2. GitHubでの登録など、本人が使えるログイン方法を選ぶ。
3. 用途・利用条件と商用利用に適したプランを確認する。有料プランは本人が選択する。
4. アカウント作成が終わった時点で、接続方法を確認する。作成しただけでこの作業環境へログインが共有されるわけではありません。

この段階ではGitリポジトリのインポート、ドメイン設定、本番デプロイは行いません。

## プレビューだけを作る手順

本人のVercelアカウントでログインできる実行環境から、ソースのルートで以下を行います。

```sh
cd /workspace/tunique
npx vercel login
npx vercel
```

`npx vercel` はこの環境での実行・認証・デプロイをまだ検証していません。
チームとプロジェクトを選び、フレームワークがNext.js、Node.jsが24.x、ビルドが `npm run build` であることを確認します。
本番公開前は `--prod` を付けません。正式ドメインの割り当ても行いません。
商用サイトに適した利用条件・プランを確認してください。有料契約は本人の判断で行います。

GitHubからの新規インポートは本番デプロイにつながる場合があるため、プレビュー作成と本番公開を区別します。
現在はCLIでのPreviewデプロイを先に確認する想定です。Git連携は公開フローとブランチ運用を決めてから設定します。

## URLが発行された後

1. デプロイ種別がPreviewであることを確認する。
2. Previewの閲覧制限を必要に応じて設定する。noindexは閲覧制限の代わりではありません。
3. スマートフォンからHOME・サービス・ABOUT・CONTACTのリンクと画像を確認する。
4. OGP画像のURLがlocalhostではなく発行されたプレビューURLを参照していることを確認する。
5. 受付準備中の表示と未送信状態を確認する。
6. 正式ロゴ、プロフィール写真、受付窓口、個人情報の管理方法を確定する。
7. 管理者の明示承認を得てから本番公開・独自ドメイン接続へ進む。

公開に必要な詳細確認は `RELEASE-CHECKLIST.md` を参照してください。

## 手元にソースを移す場合

`release/tunique-preview-source.zip` は、実行に必要なソース・選定写真・ロックファイルと確認資料を含む引き渡し用ZIPです。
依存関係・ビルド済みファイル・原本写真保管フォルダ・認証情報は含みません。展開後、Node.js 24で `npm ci` と `npm run build` を実行します。
このZIPはVercelの編集画面へそのままインポートできることを確認したものではありません。展開したフォルダからCLIを使うか、適切なGitリポジトリへ配置します。

- ユーザーはVercelアカウント作成済みと回答。
- 公式CLI 65.7.0を `/workspace/tools/vercel/` に準備。アプリの依存関係には追加していません。
- CLIの設定先は `--global-config /workspace/tools/vercel/auth` を使用。認証情報をリポジトリやZIPへ含めません。
- 現時点では認証未完了。`vercel.com` へのHTTPSがクラウドの通信ポリシーで403になっています。

- Node.js標準fetchも既存のHTTPSプロキシを使うよう、CLI起動時に `NODE_USE_ENV_PROXY=1` を指定します。TLS検証を無効化したり、プロキシを迂回したりしません。
